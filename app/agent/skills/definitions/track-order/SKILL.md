## 订单物流查询流程（售后）

当用户想查订单或物流时，按以下流程处理。

### 第一步：确认订单

- 用户给了订单号 → 直接调用 `query_order(order_id=...)` 查单笔详情
- 用户没给订单号 → 调用 `query_order()`（无参）列出全部订单摘要，请用户确认是哪一笔

### 第二步：查询物流

- 对确认的订单调用 `query_logistics(order_id=...)` 获取轨迹
- **已签收**：告知签收时间与签收方式
- **在途**：告知最新节点位置与预估送达（以轨迹原文为准，不要自己估算时间）
- **无物流信息**：说明订单可能还未发货，建议用户稍后再查或联系商家

### 第三步：汇总回复

- 报告结构：订单号 → 订单状态 → 承运商与运单号 → 最新节点 → 下一步提示
- 所有节点时间与事件照抄工具返回，不要改写
- 用户问"什么时候到"而轨迹中没有承诺时间时，如实说明"轨迹未提供预计送达时间"

### 注意事项

- 退货中的订单走逆向物流，节点事件会显示"退货件"，向用户解释这是寄回商品的运动轨迹
- 用户在查询物流时顺带提出退换货诉求 → 转入退换货流程（process-return 技能）
