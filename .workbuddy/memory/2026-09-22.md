## 压缩模块深度分析
读透 `compaction.py` / `summarizer.py` / `product_tracker.py` / `context_budget.py` / `prompts/summarizer.py` + `8-压缩重新设计.md` + `test_compaction.py`。方案本身（破坏性删除 + 六段填表 + 商品记忆独立存储 + 先摘要后删除的事务）站得住，问题在四个细节：

1. **商品 ID 正则在中文语境失效（已实测证明）**：`_PRODUCT_ID_PATTERN = r"\b(?:LP|PH|HP)-\d+\b"` 依赖 `\b`，而 Python `re` 的 `\w` 在 Unicode 下含中文 → `"推荐LP-01这款"` / `"价格LP-01为5999"` / `"商品：LP-01推荐"` **全部匹配不到**；只有前后是非单词字符（空格、`**`、全角括号）才命中。同一模式还出现在 `app/evaluation/metrics.py:48`（`_ID_PATTERN`）与 `tests/test_multi_agent.py:612`。影响：product_tracker 来源一漏登记壳子；评测的数值保真 / 幻觉断言**漏检**（false negative，评测偏宽松）。
2. **summarizer 未传 reasoning_effort**（`summarizer.py:66-71`）：`summary_max_tokens=2048` 与推理模型思考共享预算，思考吃光 → `finish_reason='length'` → `raise ValueError` → 压缩 fail-closed 失败。与 router 的 2026-09-16 修复**同根因**——router 已修（low + 2048），摘要这条没跟上。
3. **`SubAgent.last_prompt_tokens` 只写不读**（`agents.py:71` / `186`）：D7 承诺的"真实用量校准"回路从未接通，估算至今仍是纯启发式。
4. **products 无条数 / 大小上限**：上下文里唯一单调递增的注入块。理论风险 = 压缩后总量没变小导致拒绝压缩（量级上极难触发）。另 `summary_max_chars=12000` 恒不生效——token 上限必先触发（`estimate_text_tokens >= len/3`，12000/3 = 4000 > 2048）。

另：`should_compact` 的 `enabled` 参数在产品路径恒为 True（只有测试传 False），属防御性接口，非死参数。
