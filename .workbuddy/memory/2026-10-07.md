## Router prompt 前缀顺序改造（KV cache 友好）

- 起因：回答"什么叫 KV cache 友好设计"时体检项目，发现 `router.py` 把动态 `context` 拼在固定 `ROUTER_PROMPT` **之前**、且 `{user_input}` 占位符插在规则文本中间——稳定段被推到后面，每条请求前缀都不同，前缀缓存零命中。
- 改动（2 个文件）：
  - `app/prompts/agents.py`：`ROUTER_PROMPT` 变为纯常量（去掉 `{user_input}` 占位符），末尾输出指令摘出为独立常量 `ROUTER_OUTPUT_INSTRUCTION`；模块 docstring 同步说明。
  - `app/multi_agent/router.py`：拼装改为 `blocks = [ROUTER_PROMPT, context, 用户消息, 输出指令]` 用 `"\n\n".join`，动态内容一律排在固定规则之后。import 同步更新。
- 拼装顺序：规则主体（稳定前缀 1.5k token）→ 最近对话 → 用户消息 → 输出指令。
- 等价性验证（假 client 真实调用 `Router.route` 捕获实发 prompt，与 git HEAD 版旧拼装逐块对比）：块集合相同、固定规则块逐字节相同、用户/输出块顺序不变、无残留占位符。**已验证，脚本跑完即删**。

## 项目的 KV cache 友好设计现状（体检结论）

做对的：① `context_pack.py` 六段固定段序、稳定段在前（注释显式声明为前缀缓存设计）；② `tools/manager.py` 工具定义保序（`list(...)` + 列表推导过滤，白名单 set 只做 `in` 判断不遍历），因工具定义排在请求最前，顺序抖动会全废；③ 全项目不在 prompt 注入时间戳（`datetime.now()` 只在持久化与评测脚本）。

已知取舍（未改）：① memory/summary/商品块三段易变内容夹在 prompt 与 history 之间，会使 history 每轮重算——但这是"背景指令先于对话"的语义需要，属正确性 vs 缓存收益的权衡；② 条件性省略（`if pack.summary:`）会让段数变化、消息数组错位，理论上固定段数（空段占位）更稳；③ 压缩删历史前缀换摘要，缓存必然失效，属固有代价。
